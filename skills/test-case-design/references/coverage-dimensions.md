# 覆盖维度清单

用例的 `dimension` 字段取自下面 8 个取值。`scripts/validate-cases.mjs` 中的 `DIMENSIONS` 数组与本清单一一对应，改动其中一处必须同步另一处。

| 取值 | 中文名 | 关注的问题 |
|------|--------|------------|
| `functional` | 功能 | 主流程按需求正确执行，结果符合预期 |
| `boundary` | 边界 | 临界值、最小/最大、超限一点点、临界点两侧 |
| `exception` | 异常 | 非法输入、依赖失败、超时、中断、重试后的行为 |
| `permission` | 权限 | 角色差异、越权访问、数据可见范围 |
| `data` | 数据 | 字段精度、格式、枚举取值、空值、大数据量、跨字段一致性 |
| `concurrency` | 并发 | 并发写入、重复提交、竞态、幂等 |
| `performance` | 性能 | 响应时间、吞吐、容量上限、资源占用 |
| `compatibility` | 兼容 | 端/版本/浏览器/协议版本差异下的行为 |

## 逐维度检查清单

对每个可测试需求条目，逐条问"这一条适用吗"，不适用的在报告里写明理由。

### functional（功能）
- 需求描述的行为是否都走到了？每条动作的输出是否符合需求原文？
- 同一功能的多个路径（创建/查询/更新/删除）是否都有用例？
- 步骤与预期是否可判定：预期里要能看出"看到什么就算通过"。

### boundary（边界）
- 取值范围的两端与两端外一格：下界-1、下界、上界、上界+1。
- 空值与零值：空串、null、0、"0"、单个字符。
- 长度/数量/金额的边界：0、1、上限、上限+1。
- 边界点两侧各一条用例，因为两侧走的是不同代码分支。

### exception（异常）
- 输入不合法时系统给什么反馈（错误码/提示语/是否泄漏内部信息）。
- 依赖不可用、超时、返回脏数据时的降级行为。
- 操作中途失败后的状态：是否留下半成品数据，是否可重试。
- 异常路径下是否仍然保证数据一致。

### permission（权限）
- 每个角色对同一资源的允许与拒绝行为（正向 + 反向都要有用例）。
- 越权路径：改 URL 参数、换 token、直接调底层接口。
- 数据可见范围：本人/本部门/全量。

### data（数据）
- 字段类型、精度（小数位）、单位、字符集、是否允许空。
- 枚举字段的合法值与非法值。
- 跨字段一致性：结束时间晚于开始时间、金额合计等于明细之和。
- 大数据量与特殊字符：超长文本、emoji、引号、换行、SQL 关键字。

### concurrency（并发）
- 同一资源被两个请求同时修改的结果（最后写入生效还是被拒绝）。
- 重复提交/双击是否幂等。
- 计数型资源（余额、库存、配额）的并发扣减是否超卖。
- 并发下是否出现脏读、脏写。

### performance（性能）
- 需求中给出的时限/容量指标：P95 响应时间、单次处理量上限。
- 规模增长时的表现：数据量放大 10 倍后的耗时与内存。
- 长时间运行的稳定性（如果需求涉及）。

### compatibility（兼容）
- 端与版本差异：Web/移动端、不同浏览器、客户端版本、协议版本。
- 向后兼容：旧数据/旧客户端调用新版本时的行为。
- 降级路径：新特性关闭后是否回到稳定行为。

## 优先级建议

优先级反映"这个缺陷漏掉的代价"，与维度正交：

- `P0`：阻断主流程、资损、数据安全/权限越权、结果错误且不可逆。典型维度：`permission`、`data`、`exception` 里的数据破坏类。
- `P1`：主流程可用但体验或效率明显受损，或次要功能完全不可用。
- `P2`：边缘场景、次要功能异常、有可接受的规避方式。
- `P3`：文案、样式、极低频路径。

用户给定优先级口径时以用户口径为准；未给定时按上表推断并在汇报中说明推断依据。

## 与设计方法的对应

维度回答"覆盖哪类风险"，设计方法回答"怎么系统性地产生这些用例"。常见组合：

| 场景 | 组合 |
|------|------|
| 长度/数量/金额有区间 | 等价类划分 + 边界值分析 → `boundary` |
| 多条件组合出结果 | 判定表 → `functional` |
| 对象有生命周期 | 状态迁移 → `functional` + `exception` |
| 参数多且互相独立 | 正交实验 → `functional` + `data` |
| 角色差异大 | 判定表（角色 × 资源） → `permission` |
| 依赖外部系统 | 场景法 + 故障注入 → `exception` |
